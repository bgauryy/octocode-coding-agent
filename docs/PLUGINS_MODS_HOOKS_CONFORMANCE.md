# Plugins, mods and hooks: conformance evidence

Part of the [plugins, skills, extensions and hooks design](PLUGINS_MODS_HOOKS.md). Pinned upstream evidence, compatibility ratings, Claude Mods host requirements and the commands that reproduce the conformance checks.

## Pinned upstream repository evidence

The source review is pinned to [openai/codex at 8eaf5fd](https://github.com/openai/codex/tree/8eaf5fd115f036d207be236009938261758e30f2) and [anthropics/claude-code at 5ed799e](https://github.com/anthropics/claude-code/tree/5ed799e5cc56bea9efff57398ca43e31d82784ff). Snapshots are research evidence, not vendored runtime dependencies.

Codex's `core-plugins/src/manifest.rs` distinguishes path arrays from inline `HooksFile` arrays. Its `executor_hooks_tests.rs` uses wrapped inline event maps. The component adapter now rejects mixed Codex arrays and requires the wrapper, while Claude mixed declarations normalize their unwrapped event maps into the common file shape. The test that previously imposed Claude's mixed-array behavior on Codex was replaced with separate source-specific cases. This is a repository-backed correction, not upstream executable conformance.

Claude's published Mods examples use `register(on, options)` and typed middleware around engine operations. They demonstrate that a native extension entry point cannot serve as a compatible Mods loader without an API bridge. The bridge remains outstanding.

## Compatibility ratings

These are evidence-based readiness estimates, not percentages of upstream features. 0 means absent; 3 means declarations or limited translation; 5 means a partial running adapter with local tests; 7 requires broad end-to-end conformance; 10 requires all applicable pinned contracts verified, including lifecycle and platform checks. Host-only services are marked unavailable rather than assigned a success score.

| Area                          | Current rating | Main reason it is not complete                                                                                                                                                                                   |
| ----------------------------- | -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

| Skills                        | 5/10           | Native discovery/invocation and plugin namespaces work; host-specific frontmatter, scoped hooks and execution restrictions need adapters                                                                         |
| Native extensions             | 6/10           | Established native API and discovery boundaries; it is not the Claude Mods API                                                                                                                                   |

## Pinned Claude Mods host requirements

The [published declarations](https://github.com/anthropics/claude-code/blob/5ed799e5cc56bea9efff57398ca43e31d82784ff/mods/types/claude-code.d.ts) identify their host as **Claude Code 2.1.277**. The inventory contains **40 engine events and 55 operation events**, in addition to classic hook events and plugin-defined nouns. These are not implemented by the native extension API. The source declaration inventory is recorded in `.octocode/octocode-workflows/hooks-compatibility/tmp/mods-event-inventory.json`.

| Bridge requirement | Source contract                                                                                                                                         | Octocode implementation decision and remaining check                                                                     |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| Module environment | Separate environment; no Node, DOM, `require`, code generation, WebAssembly or ambient timers                                                           | Build an isolated module host before activation; importing Mods through the native extension loader is incompatible      |
| Registration       | `register(on, options)`; named/glob/negated patterns, structural matchers, registration failure handlers                                                | A distinct registration owner must validate declarations and required options before activation                          |
| Middleware         | First registration outermost; repeat downstream calls, short-circuiting, cancellation and validated results                                             | Adapt actual operations at their owners; an observational event listener cannot reproduce this contract                  |
| Budgets            | Own execution time is metered; downstream and engine calls pause accounting; failure has separate grace                                                 | Tests must cover nested calls, timeouts and pending-child cancellation before loading user modules                       |
| Authority          | Managed tiers may skip only permitted downstream tiers; origin and trace accompany calls                                                                | Preserve permission ownership and managed-policy precedence; no general bypass through `$`                               |
| Engine operations  | 55 operations across model, audio, MCP, session, tools, commands, config, agents, UI, filesystem, store, clock, HTTP, process, settings and environment | Bridge each supported operation to its current owner; explicitly reject unavailable operations                           |
| Engine events      | 40 events covering tools, UI, agents, prompts, commands/config, skills, sessions, plugins, turns and engine creation                                    | Add fixtures for argument/result schemas and timing; render/stream events require surface-specific adapters              |
| Rendering          | Validated plain-data element trees, surface element tables and callback handles                                                                         | TUI and webview need separate render adapters and handle cleanup; React/Ink resemblance does not establish compatibility |

S9 therefore depends on an isolated host, a middleware dispatcher, permission-preserving owner adapters and rendering support. The declaration source narrows the target version; it does not prove that any Mod runs unchanged. P5/P6 remain missing rather than receiving a compatibility score for declaration discovery alone.

## Reproducing Codex output conformance

Normal tests consume `packages/coding-agent/test/fixtures/hooks/codex-output-contract.json` without network access or Rust. `hooks-codex-conformance.test.ts` compares all 2,816 reference decisions with the adapter. To regenerate, use Node 24.15+ to run `packages/coding-agent/scripts/generate-codex-hook-output-fixtures.mjs`; add `--check` to verify the committed corpus. This opt-in command requires Cargo and network access to the pinned GitHub sources and crates.io. It checks source hashes, compiles the unchanged upstream output parser with its wire declarations (schema-generation annotations removed), preserves the upstream license, and removes its temporary build directory. The corpus does not test process exit semantics, dispatch timing, permissions or file-patch rewriting.

## Reproducing patch and skill conformance

The retained [patch oracle](../packages/coding-agent/test/octocode/fixtures/codex-patch/ADAPTATIONS.md) compares parsing and exact transformed bytes across 140 cases. The [skill metadata oracle](../packages/coding-agent/test/fixtures/codex-skill-metadata/ADAPTATIONS.md) compares YAML acceptance and policy values across 103 cases. Both retain pinned source hashes, adaptations, licenses, locked Rust dependencies and offline replay commands. Normal tests consume saved fixtures without invoking Rust. These corpora establish their narrow parser contracts; real-session tests separately cover the local execution and policy owners.

The [mention parser corpus](../packages/coding-agent/test/fixtures/codex-skill-mentions/corpus.json) retains 39 cases from the same pinned Codex revision. Its [manifest](../packages/coding-agent/test/fixtures/codex-skill-mentions/manifest.json) records the unchanged Rust source hash; run `python3 packages/coding-agent/test/fixtures/codex-skill-mentions/replay.py` to rebuild the retained oracle with locked offline dependencies and verify expected results. Selection and resource eligibility are covered by separate local tests; parser agreement alone does not prove upstream session equivalence.

## Reproducing Claude permission decisions

The retained [Claude permission replay](../packages/coding-agent/test/octocode/fixtures/claude-permissions/replay.py) runs eleven isolated cases against an installed executable and compares effect markers and PermissionRequest counts. [Observed results](../packages/coding-agent/test/octocode/fixtures/claude-permissions/observed.json) record Claude Code 2.1.309 and its executable hash. Run `python3 packages/coding-agent/test/octocode/fixtures/claude-permissions/replay.py --claude /absolute/path/to/claude --node /absolute/path/to/node`. It requires the recorded version and hash by default; `--allow-identity-mismatch` explicitly permits researching another executable without making it the pinned baseline.

The [replacement replay](../packages/coding-agent/test/octocode/fixtures/claude-permissions/rewrites.py) accepts the same arguments and verifies [19 cases](../packages/coding-agent/test/octocode/fixtures/claude-permissions/rewrite-cases.json), with [retained observations](../packages/coding-agent/test/octocode/fixtures/claude-permissions/rewrite-observed.json). It covers replacement validation, empty objects, empty permission updates, competing handlers and an actual local MCP permission host. Delayed-handler cases prove the recorded bounded races, not every possible scheduling order. Interactive prompts and complete execution defaults remain outside this corpus.

The [file replacement replay](../packages/coding-agent/test/octocode/fixtures/claude-permissions/file-rewrites.py) verifies fourteen isolated Write/Edit cases with the same arguments and identity guard. Its [observations](../packages/coding-agent/test/octocode/fixtures/claude-permissions/file-rewrite-observed.json) include an actual prior Read, replacement-path checks, unknown fields, replace-all behavior, original anchor validation and unread-target refusals. These are individual vendor calls; they do not prove Octocode's native multi-query batch transaction, which has separate runtime tests. The separate [replace-all replay](../packages/coding-agent/test/octocode/fixtures/claude-permissions/replace-all.py) retains eleven vendor cases covering partial reads, stale contents, exact-match priority, quote fallback, CRLF, non-overlapping matches and rejected broader normalization; its [observations](../packages/coding-agent/test/octocode/fixtures/claude-permissions/replace-all-observed.json) record the pinned executable results.

The [permission-update replay](../packages/coding-agent/test/octocode/fixtures/claude-permissions/permission-updates.py) retains 27 pinned vendor cases; its [observations](../packages/coding-agent/test/octocode/fixtures/claude-permissions/permission-update-observed.json) distinguish ordered calls and restart effects. These observations define tests for the ongoing local implementation; they are not a claim that Octocode supports every update.

The runner supplies a local mock provider, temporary settings and a dummy credential. It does not use a live provider account. It terminates its owned process group on timeout and removes temporary configuration. The fixture uses POSIX process handling; Windows replay remains unverified. These cases establish the permission-request approval/replacement boundary, not full shell grammar, source discovery or host conformance.

The [Bash grammar replay](../packages/coding-agent/test/octocode/fixtures/claude-permissions/grammar.py) uses the same isolated harness and executable identity guard. Run it with the same `--claude` and `--node` arguments as the permission replay. Its [47 retained cases](../packages/coding-agent/test/octocode/fixtures/claude-permissions/grammar-cases.json) and [observed results](../packages/coding-agent/test/octocode/fixtures/claude-permissions/grammar-observed.json) distinguish quoted literals, executable segments, raw redirect positions, whole-command versus leaf rules, broad grants, parameter-selector ambiguity and malformed-shell failures. This corpus is narrower than the complete Bash language and does not cover PowerShell or every wrapper.

The [wrapper replay](../packages/coding-agent/test/octocode/fixtures/claude-permissions/wrappers.py) uses the same arguments and harness for [71 cases](../packages/coding-agent/test/octocode/fixtures/claude-permissions/wrapper-cases.json). Its [observations](../packages/coding-agent/test/octocode/fixtures/claude-permissions/wrapper-observed.json) distinguish successful command execution from permission-selection evidence when a wrapper or option is unavailable. No-input `xargs` probes are labeled separately; stdin-fed cases establish the executable path. These results cover the recorded executable and environment, not every platform or wrapper option.
