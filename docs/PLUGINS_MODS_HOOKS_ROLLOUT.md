## Canonical patch execution in the file owner

The C11/C12 implementation adds `{patch: string, reason?: string}` as an alternative to native `{queries: [...]}` on the existing `file` tool. The two modes are mutually exclusive. Native queries keep their current failure behavior; canonical patches follow the pinned Codex preparation and execution order. A separate `apply_patch` tool or filesystem implementation inside hooks would duplicate ownership and is not selected.

The [pinned invocation verifier](https://github.com/openai/codex/blob/8eaf5fd115f036d207be236009938261758e30f2/codex-rs/apply-patch/src/invocation.rs#L180) prepares every operation and rejects duplicate resolved source paths before execution. A missing later Delete or invalid later Update therefore prevents an earlier Add. Runtime failure during mutation can still leave earlier effects; this is not a rollback transaction.

Implementation and verification order:

1. Add a pure parser and chunk transformer in the shared contract layer, with upstream attribution; keep filesystem effects in the file subsystem. Compare exact bytes and selected locations against pinned fixtures for Update, Move, EOF, whitespace matching and mixed line endings.
2. Extend the existing tool schema and shared mutation-target discovery. Permission review, reservations, provenance and activity reporting must include source and destination paths.
3. Prepare all changes through existing read/stale guards before the first mutation. Commit through existing mutation queues, locks and cancellation checks; retain checkpoints for both move paths. A source is removed only after its destination write succeeds.
4. Make accepted Codex hook rewrites select canonical mode, retaining the exact patch text for successful post observation. Keep native/Claude projections separate and fail explicitly when translation cannot preserve meaning.
5. Replay real-session tests for preparation failure, update/move bytes, partial reads, stale/racing files, destination denial, cancellation and rewind. Keep the native query regression suite unchanged.

The competing per-query `type: patch` approach fits existing rendering but obscures whole-patch preparation, multiple targets and stop-on-error semantics. Canonical mode makes those differences explicit. Retained Octocode read/permission safeguards and unsupported remote environment routing remain documented host differences. Native edits still need a reviewed-snapshot projection; syntax-only conversion cannot establish equivalence.

It adds no discovery roots and does not execute dependency declarations.

Implementation and verification order:

2. Apply `policy.allow_implicit_invocation: false` to the existing model-catalog visibility control while preserving explicit invocation. Existing native opt-out remains effective.

A prefix-only substitution would not reproduce that contract. Interface presentation and dependency activation remain K8 work; parsing their declarations alone is not support.

## Logical turns and consumed input

C10 and E7 share an ordering gap. The pinned Codex [`inspect_pending_input`](https://github.com/openai/codex/blob/8eaf5fd115f036d207be236009938261758e30f2/codex-rs/core/src/hook_runtime.rs#L634) uses the active turn context when input is consumed. The earlier implementation dispatched both source profiles from admission-time `input`, before a queued follow-up belonged to its future turn. A model-iteration counter could not supply the missing identity. The following plan has now passed focused implementation and independent actual-session checks; the repeated full suite also passes.

1. Add a narrow awaited input-consumption boundary to the reusable agent loop, carrying initial, steering or follow-up origin. Keep host policy and identity allocation in `AgentSession`. The boundary must run before accepted message persistence and the provider request.
2. Allocate an opaque logical turn identity in the session owner. Preserve it across tool iterations, steering, retries, compaction and Stop continuation. A consumed follow-up batch starts a new identity; admission alone cannot switch the active turn. All-at-once follow-ups share their batch identity.
3. Expose the active identity through extension context and project it only into source events that define it. Move Codex `UserPromptSubmit` to consumption while retaining native and Claude admission behavior. Preserve original processed user text alongside queued input; defer Codex skill selection until the hook accepts that input. Generated bodies must not become new mentions.
4. Apply decisions per input item. The pinned [`run_hooks_and_record_inputs`](https://github.com/openai/codex/blob/8eaf5fd115f036d207be236009938261758e30f2/codex-rs/core/src/session/turn.rs#L949) keeps accepted items in a mixed batch, records blocked-item context, and stops when input was blocked with no accepted user item. Do not replace this with an unconditional batch veto.
5. Begin with failing reusable-loop and actual-session tests for identity lifetime, queue modes, mixed/all-blocked batches, cancellation, retry and generated-message bypass. Preserve queue accounting, tool-result pairing and cleanup. Verify source-specific input timing separately from ordinary extension input hooks.

The implementation preserves admission-time native slash/template expansion and the existing `before_agent_start` prompt. Only Codex mention selection and reads defer until consumption-hook acceptance. Selected follow-up batches allocate identity before continuation preparation, so compaction observes the new turn. All-blocked input retains context and settles without reusing an old assistant response for Stop or retry. Independent shell-hook/provider acceptance passes 27 cases, including accepted-context ordering, follow-up preparation identity, clearing queues during a selected batch and cancellation after an earlier item is persisted. Idle manual compaction remains without a turn ID.

This is a prerequisite for subagent start/stop payloads and model-request events, not their implementation. Rollback removes the new source-profile consumption route while retaining native admission behavior; an unavailable identity must remain absent rather than be derived from a tool ID or model iteration.

## Input persistence and native cancellation corrections

The first broad C10 run exposed five existing native concurrency/cancellation regressions despite focused acceptance passing. The corrections now pass all 41 unchanged tests in the three affected native suites; the repeated full suite now passes. The pinned Codex [per-item input recorder](https://github.com/openai/codex/blob/8eaf5fd115f036d207be236009938261758e30f2/codex-rs/core/src/session/turn.rs#L969) also persists each finalized item before inspecting the next. The earlier whole-batch result could not preserve that timing if a later hook was cancelled; finalized items now commit incrementally through the agent loop.

1. Reproduce the existing concurrent-message, custom-run cancellation and session-replacement failures without changing their assertions. Restrict the new no-sampling termination to consumed input gates; retain native aborted-response and persistence behavior for unrelated cancellation paths.
2. Let the generic loop own incremental accepted-message persistence through an awaited narrow callback. The session evaluates each user item and commits its finalized message/context before checking the next item. Avoid direct transcript writes from the hook adapter or a second inventory of messages to replay after cancellation.
3. Add a failing actual-session case that holds the second shell hook: the first accepted item and context must already be recorded. Cancelling the second must retain the first while preventing later input, context, skill reads and provider calls. Preserve system/tool declarations and handler ordering.
4. Repeat the affected native and Codex acceptance tests, then the full isolated suite and offline build. Do not mark C10 verified on focused tests alone. Rollback of the new seam must preserve the pre-existing native cancellation contract.

## Subagent lifecycle adapters

E12 follows the logical-turn work. Pinned Codex [start dispatch](https://github.com/openai/codex/blob/8eaf5fd115f036d207be236009938261758e30f2/codex-rs/core/src/hook_runtime.rs#L127) targets the child turn; [stop dispatch](https://github.com/openai/codex/blob/8eaf5fd115f036d207be236009938261758e30f2/codex-rs/core/src/hook_runtime.rs#L352) provides separate parent and child transcript paths. Claude's [SubagentStart and SubagentStop contracts](https://code.claude.com/docs/en/hooks#subagentstart) likewise require child context delivery and continuation. A parent process-exit observer cannot implement a stop gate.

1. Establish a child lifecycle identity at the existing subagent process owner, including the parent session/transcript and the child's session/profile. Do not substitute a team display name for the Codex child-session identifier. Preserve cleanup, cancellation, permission inheritance and the existing child hook opt-in; document that policy difference from the vendors.
2. Supply live permission metadata through a callback from native composition, which already owns `Permission.mode`. Read it per dispatch. Codex’s coarse approval labels map native `full` to `bypassPermissions` and approval-capable modes to `default`. For Claude, document this as an adapter label with local policy differences: native `workspace` also allows shell actions and must not be represented as equivalent to `acceptEdits`. Standalone hook registrations without a live owner must diagnose missing required metadata instead of inventing a default.
3. Route source-profile SubagentStart in the child before its first provider request with an active logical turn. Match the agent type and inject returned context into the child. Start output cannot prevent child creation. Keep native lifecycle hooks unchanged and avoid dispatching an additional source SessionStart for the same child start. Verify resume behavior separately for each source profile.
4. Route SubagentStop through the child's existing before-settlement continuation owner. Keep child and parent transcript fields distinct, retain the existing continuation cap and cancellation checks, and omit events for failed or cancelled work unless the source contract requires them. A blocked stop continues the child; it must not continue the parent.
5. Add source-specific schemas, matcher selection, output parsing and actual shell-hook acceptance before declaring support. Begin with failing tests for child-only context, identity, parent/child transcript routing, one blocked stop followed by completion, resume, disabled hooks and cancellation. Verify main-session Stop remains unchanged.
6. Record unsupported internal vendor agents, vendor transcript formats, parent background-task inventories and source role differences explicitly. Rollback removes these source routes and identity handoff without changing native subagent supervision.

The actual-child resume test exposed an existing startup classification gap: an initial CLI runtime opening a saved session defaults to `startup`, while explicit runtime switches supply `resume`. Correct this in the session construction owner from loaded session state, preserve explicit lifecycle reasons, and verify new, reopened and empty saved sessions. Hook adapters must not guess resume from agent names or replay historical messages. Ten independent actual-child process cases now pass: both protocols cover startup context, child-only continuation, distinct IDs/transcripts, inherited permission narrowing, opt-out, resume cadence, cancellation and provider failure. Focused review fixes, the repeated full suite, offline build and compiled SDK/wire smoke now pass. The focused checks include live permission changes, oversized context deduplication, active-context reinsertion and mixed native/source termination precedence. This does not establish full host equivalence.

## Interrupted-turn hooks

1. Trace every native abort caller before selecting the event boundary. Retain the interrupted logical turn identity through settlement. Distinguish explicit interruption from replacement, shutdown, failure and successful completion; do not infer the reason from provider error strings.
2. Dispatch once from the existing session cancellation/settlement owner after the interrupted work has stopped and its transcript is recorded. Use a fresh, bounded cancellation scope so the already-aborted provider signal does not suppress cleanup. Preserve deadlock avoidance when an extension requests abort inside a callback.
3. Accept Interrupt only in the Codex source profile. Ignore matchers; use its one-second default and three-second timeout cap. Command async execution and MCP handlers have source-specific behavior; SessionEnd's forced-synchronous rule must not be copied onto Interrupt.
4. Supply actual session, turn, model, permission and nullable transcript fields. Validate the distinct output object: only optional `systemMessage` is accepted. It is observational, cannot undo cancellation, inject continuation context or restart the model, and failures remain diagnostic.
5. Extend the pinned Rust output corpus through its actual interrupt parser. Begin with actual-session failing tests for a held provider request followed by interruption, single delivery after repeated abort, timeout/cancellation, no-event cases, source metadata, output validation and no extra provider request. Verify RPC/CLI interruption and existing native cancellation behavior independently.
6. Keep executor-service request metadata and unavailable vendor services explicit. Rollback removes the source event route while preserving the native abort semantics and any owner-level reason distinction needed by existing callers.

Implementation review added regression checks before fixing three problems: independent abort callers returning before observer cleanup; pending records not yet saved when preparation failed; and invalid synchronous hook output disappearing in headless sessions. At the E14 verification point, the pinned Rust output corpus covered 2,320 cases across ten events. All 16 frozen command/RPC/SDK and configured MCP replays pass, as do the full repository tests and root checks. The offline build and three built-CLI cancellation/MCP replays also pass.

## Permission-request integration (implementation in progress)

This event belongs at an unresolved permission decision, including a request that cannot display a dialog. Claude permits input replacement and permission updates on an allow, but rechecks deny/ask rules; an exit-2 script without a decision does not deny by itself. Its payload omits `tool_use_id`. [Claude contract](https://code.claude.com/docs/en/hooks#permissionrequest).

Codex accepts allow/deny without input replacement. Any deny wins across handlers, and exit 2 with a nonempty stderr reason denies. Child identity, model and turn fields come from the actual request context. [Pinned Codex owner](https://github.com/openai/codex/blob/8eaf5fd115f036d207be236009938261758e30f2/codex-rs/hooks/src/events/permission_request.rs).

The implementation dispatches from `Permission.check` after automatic mode/grant resolution and before headless denial, child relay or a dialog. The tool wrapper supplies a bounded immutable JSON invocation snapshot. A matching call ID and live execution are required; nested and parallel calls have separate contexts. Lifetime is checked again after hooks and destructive snapshots finish, so a late allowance cannot revive a completed call. Context copies retain the descriptor's live status. Custom SDK arguments that cannot be represented leave the snapshot unavailable without changing their execution. The pre-execution gate supplies its actual event explicitly; tool-less checks remain native-only.

Native composition connects the permission and hook owners. Refusals and allowances use the existing audit and activity paths. Claude denial with `interrupt: true`, and universal `continue: false` even beside a nested allow, record the refusal before stopping the turn. Required invalid handlers never start a process. Invalid Codex output contributes no decision by default, matching the pinned runtime; a separate valid allow can still apply. Local projection failures are different: a matching source hook that cannot receive a faithful file input causes refusal. Every projected Claude query must allow a native file batch.

The explicit context design replaces the proposed async-local alternative because current internal callers retain their context. Tests reproduce expiration during an awaited hook, custom non-JSON SDK arguments, and cross-profile projection refusal before fixing them. The pinned Rust output corpus now includes 496 PermissionRequest cases. Independent final validation passes 34 actual SDK cases and five actual child-process/transport cases, including command hooks for both profiles, Claude HTTP and prompt handlers, and a configured Codex MCP server. Final replay and the full repository suite pass (3,284 core tests and 3,293 native tests, with configured skips). The offline build and 11 compiled checks also pass. Those checks assert built SDK/supervisor/child CLI identities in a staged package without source files; parent workspace library aliases and registry portability remain separate. Child hooks resolving before an unavailable parent relay are verified; successful relay fallback is not claimed by these runtime cases.

A partial source-rule reader/evaluator is implemented. Outer Bash replacement passes 30 new runtime cases and a combined 288-case regression replay. The full repository suite, offline build and all 30 compiled cases pass. Four fresh macOS ARM standalone checks verify replacement, denial, cancellation and timeout conversion through actual RPC; file-query replacement also passes full-suite, compiled and standalone checks; typed-shell replacement remains unfinished. Nonempty permission-update arrays still produce diagnostics without applying their allow; empty arrays are no-ops. Claude prompt hooks may run here, but `ok: false` has no decision effect; agent handlers are unsupported for this event. [Claude handler contract](https://code.claude.com/docs/en/hooks#prompt-based-hooks).

Outer Bash replacement now uses a host-owned transaction before execution. It collects the winning proposal without mutating the frozen invocation, validates the replacement against the registered tool schema, and rechecks source rules, reservations and native protections. It commits only while the invocation is active, executes once, and audits original and effective input. Revalidation does not recursively dispatch another PermissionRequest hook. Delegated hook approval answers ordinary native asks; a matching replacement source ask cannot inherit that approval.

The retained upstream probes establish the following boundaries:

- A replacement with no matching source rule runs in manual/headless mode. A replacement matching an ask rule is refused without a second permission-host callback. Interactive UI behavior remains unverified: an isolated interactive attempt stopped at the vendor connectivity preflight before any model request.
- An empty replacement object preserves the input but still triggers rule checking. Invalid command types fail validation. An empty permission-update array is a no-op.
- The first effective Claude permission decision wins, and slower handlers are cancelled and drained—even when a slower reply would deny. Codex and cross-profile precedence retain their separate contracts.

The shared Claude Bash adapter serves PreToolUse and PermissionRequest. It converts source milliseconds to native seconds and maps `run_in_background` to `background`. A nonempty replacement replaces the input, so omitted options do not survive; unknown source properties cannot inject native-only execution options. Positive 100 ms Node-command probes confirm that both hosts background long-running non-sleep work, while the sleep timeout case terminates. The native execution owner therefore retains its existing behavior. Explicit deadline probes do not establish equivalence of defaults, maximums or background-job lifetime. Negative source timeouts currently differ, and PowerShell needs a separate source contract. [Claude Bash input fields](https://code.claude.com/docs/en/hooks#pretooluse-input).

File-query replacement now stages indexed proposals in the native file owner. Original read and edit requirements are checked before source hooks. The candidate batch is validated before any writes, including source rules, read coverage, edit spans, reservations and hard state protections. Candidate approval uses effective previews. Canonical target identities are checked after approval and again at the locked mutation boundary. The original immutable invocation remains available for audit, while committed arguments and pre-effect Codex patch snapshots feed post-tool hooks.

The shared Claude file adapter serves PreToolUse and PermissionRequest without a file-to-hook dependency. Unknown source properties cannot inject native options. The shared edit engine and both native schemas now accept optional `edits[].replaceAll`, mapped from Claude `replace_all`. True enumerates non-overlapping matches against the original LF-normalized content; replacement text is never searched again. Exact spelling takes priority over smart-quote fallback. Expanded spans reuse overlap validation and atomic writes, and line endings are preserved. Partial reads are not upgraded to full coverage; stale files retain current bytes outside the matched spans, while unread/context-expired guards remain.
