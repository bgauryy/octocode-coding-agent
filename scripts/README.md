# Repository scripts

Run a script through its root `yarn run` entry where one exists; the rest are manual tools or modules the others import. Each module's test sits beside it (`*.test.mjs`, `*.test.ts`) and runs with `yarn run test:scripts` (every folder but `agent-eval/`). The full verify table is in [DEVELOPMENT.md](../DEVELOPMENT.md#verify).

| Folder        | Holds                                                                                   |
| ------------- | --------------------------------------------------------------------------------------- |
| `build/`      | The coding-agent bundle and its assets, the webview page bundle, binaries, favicon      |
| `check/`      | `yarn run check` and the boundary, link and smoke checks it runs                        |
| `release/`    | Versioning, packing, local installs, publishing; `install-lock/` for the installer lock |
| `test/`       | The test launchers and the host's one-full-run lock                                     |
| `lib/`        | Yarn and npm launchers and the source-workspace map, shared by the folders above        |
| `agent-eval/` | Decides whether an agent change ships: [README](agent-eval/README.md)                   |

## build/

| Script                      | Run with                                         | Does                                                                                                                                                                                                                                                                                                                                                       |
| --------------------------- | ------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `build-offline.mjs`         | `build:offline`                                  | Runs every workspace's `build` and `generate:prompts` side by side (the prompt generator reads source, not dist); prints each step's output whole and fails when either fails                                                                                                                                                                              |
| `build-coding-agent.mjs`    | `build` in `packages/coding-agent`               | One Rolldown bundle (`dist/bundle/`) with small launchers, `version.js` and `help.js` (they answer `--version` and `--help` without loading the bundle) and the database writer's and archive index's workers, then runtime assets, native helpers, the Bash parser, the sandbox library's helpers, licenses and `THIRD_PARTY_NOTICES.md`                  |
| `sandbox-vendor.mjs`        | `build-coding-agent.mjs`, `publish-stage.mjs`    | The sandbox library's prebuilt helpers (Linux seccomp filter per architecture, JVM proxy agent) copied to `dist/bundle/vendor/`, where the bundled library looks; the build fails when the library lacks one, and the publish gate when the package does                                                                                                   |
| `third-party-notices.mjs`   | `build-coding-agent.mjs`                         | License and notice texts of every package compiled into the bundle, installed or linked from outside the repository                                                                                                                                                                                                                                        |
| `copy-native.mjs`           | `build-coding-agent.mjs`, `stage-binary.mjs`     | Copies prompt Markdown and core skills without READMEs, `final/` or TypeScript, and packs the prompt Markdown into `prompts.pack.json`, which a process reads instead of each file                                                                                                                                                                         |
| `stage-bash-parser.mjs`     | `build-coding-agent.mjs`                         | Stages the Bash parser and its licenses                                                                                                                                                                                                                                                                                                                    |
| `stage-binary.mjs`          | coding-agent `build:binary`, `build-binaries.sh` | Stages what a compiled binary reads beside itself: themes, export template, roles, native skills, native helpers, and the research MCP server (`stage-mcp-servers.mjs`)                                                                                                                                                                                    |
| `build-binaries.sh`         | manual                                           | Builds platform binaries                                                                                                                                                                                                                                                                                                                                   |
| `compile-binary.mjs`        | coding-agent `build:binary`, `build-binaries.sh` | Compiles the CLI into one Bun binary from the package root, with a stub for Ink's optional devtools; `stage-binary.mjs` then stages what it reads beside itself                                                                                                                                                                                            |
| `stage-mcp-servers.mjs`     | `stage-binary.mjs`                               | Copies the MCP servers a binary runs from its own dependencies (presets with `install.hostDependency`) and, for its platform, their native package into `node_modules/` beside it, as `npm pack` would publish them from the package the coding agent resolves (the linked build in development), so the binary starts them offline without an npm install |
| `build-workspace-state.mjs` | `generate:workspace`, `check:workspace`          | Builds the webview page bundle into `packages/webview/src/state.generated.ts`                                                                                                                                                                                                                                                                              |
| `generate-favicon.mjs`      | `generate:favicon`, `check:favicon`              | Generates the favicon modules from `favicon/octocode-favicon.png` and checks they are fresh                                                                                                                                                                                                                                                                |

## check/

| Script                                                 | Run with              | Does                                                                                                                                                                                                                                                                                                                                                        |
| ------------------------------------------------------ | --------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `run-checks.mjs`                                       | `check`               | Runs the listed root scripts in parallel under the host lock, buffers output, reports every failure; notes files near the 400-line limit (`near-limit-files.mjs`)                                                                                                                                                                                           |
| `check-package-boundaries.mjs`                         | `check:boundaries`    | Package import policy; hosted workspaces (`mcp`, `acp`, `common`) never import host files; ratcheted layer baselines (`layer-import-baseline.mjs`: `core/` must not import `modes/`, `octocode/` or the MCP workspace; `octocode/` must not import `modes/`). A new edge and a stale baseline entry both fail. Specifiers come from `module-specifiers.mjs` |
| `sdk-reachability.mjs`                                 | `check:boundaries`    | Fails when the headless session factory newly reaches `tui`, `webview` or `modes/` through static value imports, or a baselined edge is gone                                                                                                                                                                                                                |
| `check-db-boundary.mjs`                                | `check:db-boundary`   | Keeps `prepare`, `db.exec` and `node:sqlite` imports inside `packages/db/src/`                                                                                                                                                                                                                                                                              |
| `check-mcp-boundary.mjs`                               | `check:mcp-boundary`  | Keeps imports into `packages/mcp/src/` from other workspaces on its `api.ts` (the bundle entry may re-export the client subpaths)                                                                                                                                                                                                                           |
| `check-live-tests.mjs`                                 | `check:live-tests`    | Fails when a default run would collect a paid `*.live.test.ts` file or a credentials-gated test, or a workspace with live files has no `test:live` script                                                                                                                                                                                                   |
| `check-doc-links.mjs`                                  | `check:doc-links`     | Relative Markdown links in `docs/`, the coding-agent docs and package READMEs: the target file and each `#anchor` (GitHub heading slugs) must exist                                                                                                                                                                                                         |
| `check-workspace-subpaths.mjs`                         | `check:subpaths`      | Every `@octocodeai/<workspace>/<subpath>` that source imports is listed in that workspace's `exports`                                                                                                                                                                                                                                                       |
| `check-browser-smoke.mjs`                              | `check:browser-smoke` | Bundles `browser-smoke-entry.ts` and `agent-treeshake-smoke-entry.ts` with Rolldown: no Node imports, selective-provider tree shaking                                                                                                                                                                                                                       |
| `acp-workspace.test.mjs`, `mermaid-lazy-heap.test.mjs` | `test:scripts`        | ACP has one source owner and ships inside coding-agent without a private runtime dependency; the bundled Mermaid script and the generated web page scripts stay off the heap until asked for                                                                                                                                                                |

## release/

| Script                                                                | Run with                                                                | Does                                                                                                                                                                                                             |
| --------------------------------------------------------------------- | ----------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `release.mjs`, `sync-versions.js`, `publish.mjs`, `release-notes.mjs` | `release:*`, `version:*`, `publish`, `publish:dry`, `release:fix-links` | Versioning, notes, publishing. `publish.mjs` gates on a clean tree, dependency versions on npm, tarball checks (`publish-stage.mjs`) and an install plus real session from the tarball (`publish-preflight.mjs`) |
| `pack-packages.mjs`                                                   | `pack:packages`                                                         | Packs every public package into one local artifact set (`package-artifacts.mjs`), `link:` dependencies as absolute `file:` references                                                                            |
| `check-package-install.mjs`                                           | `check:package-install`                                                 | Installs each packed package in its own consumer (`local-package-install.mjs`) and smoke-tests the CLI (`coding-agent-smoke.mjs`)                                                                                |
| `local-release.mjs`                                                   | `release:local`                                                         | Local release candidate                                                                                                                                                                                          |
| `pack-smoke.mjs`                                                      | `pack-smoke:testkit`                                                    | Packs the agentic testkit, installs it with Vitest in a fresh project (network) and runs the README's quickstart                                                                                                 |
| `stage-registry-release.mjs`                                          | manual                                                                  | Stages a release in a disposable registry ([DEVELOPMENT.md](../DEVELOPMENT.md#validate-a-registry-release-candidate))                                                                                            |
| `use-local-packages.mjs`                                              | manual                                                                  | Points a consumer project at locally packed packages                                                                                                                                                             |
| `install-lock/generate-coding-agent-install-lock.mjs`                 | `install-lock:coding-agent`, `check:install-lock:coding-agent`          | Installer lock, built and validated by `install-lock/install-lock-*.mjs`; see [install-lock](../packages/coding-agent/install-lock/README.md)                                                                    |

Shared by the scripts above: `registry-release.mjs` (registry manifests and locks), `release-packages.mjs` and `package-workspaces.mjs` (the public packages), `local-dependencies.mjs` (`link:` siblings installed from their checkout), `coding-agent-consumer-smoke.mjs` (copied into an installed package by the smoke test).

## test/

| Script                  | Run with                                                            | Does                                                                                                                                                                                                                                                                                                                  |
| ----------------------- | ------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `test-workspaces.mjs`   | `test` (`./test.sh` wraps it in isolation)                          | Script tests plus every workspace's tests, continuing past failures, then lists them                                                                                                                                                                                                                                  |
| `test-coding-agent.mjs` | `test` in `packages/coding-agent`                                   | The core, native and e2e suites in turn (`run-test-suites.mjs`), stopping on cancellation                                                                                                                                                                                                                             |
| `full-run-lock.ts`      | `run-checks.mjs`, vitest global setup (`vitest.run-lock.global.ts`) | One full suite or check at a time on this host: a second waits, naming the holder; a dead holder's lock is taken over (`node scripts/test/full-run-lock.ts --status` exits 0 when the lock is free, removing a dead holder's lock, and 1 naming the holder: use it as a `wait` check instead of testing `owner.json`) |

## lib/

`yarn-command.mjs` runs the repository's pinned Yarn, `npm-command.mjs` runs npm, and `source-workspaces.mjs` maps the private source workspaces to the host that compiles them in.
