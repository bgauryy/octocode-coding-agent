# Changelog

Entries are shown once by `octocode` after an update and on demand with `/changelog`. Each heading names the package version; earlier releases predate this file.

## [Unreleased]

- `mcpExposure` defaults to `"usage"`: an MCP tool and the deferrable native tools are declared in full only when sessions of the same role often use them (at least 10% of the last 7 days' sessions that declared them), and are otherwise declared with their description and top-level fields. A busy folder no longer declares every tool it touched today in full, so the first request is much smaller. `"mcpExposure": "recent"` restores the previous rule.
- **Renamed to Octocode Agent.** The npm package is now `@octocodeai/octocode-agent` (install it in place of `@octocodeai/octocodecode`); the banner reads OCTOCODE AGENT. The `octocode` command, your settings, sessions and sign-ins in `~/.octocode/octocodecode/` stay as they are. Skills can exclude Octocode with `excluded-hosts: octocode-agent`; `octocode-code` still works.
- Idle-item nudges are skipped when the run that just ended was woken about that item or wrote it, or when a running background `bash` job names it with the new optional `item` argument (`coordinate list` shows the job as work on that item); the turn line counts skipped nudges. Every woken batch shows one `⚡ woke` row (also for the nudge, graph notice, hook feedback and retry wakes that showed nothing before). `subagents.wakeHoldSeconds` (default off) merges wakes that arrive seconds apart into one turn.
- Fixed: a session whose last record was cut off by a crash, kill or power loss resumes and keeps being written, instead of failing every write with "incomplete final record". The partial record stays in the file as a skipped line, and an `octocode-session-recovery` entry records where it is.
- Fixed: a session lock left by a killed or crashed process is taken over at once when its recorded owner (pid, host and start time) is verifiably gone; restarting no longer waits up to 10 s, blocks the screen for seconds, or leaves the database mirror behind.
- `--rpc-lean-events` no longer repeats a finished block in `text_end`, `thinking_end` and `toolcall_end` updates, and ACP workers use lean events. RPC and JSON output serialize a large message once per run (the bytes written are unchanged), and the API bridge redacts and saves a long answer once.
- Fixed: closing the terminal window (SIGHUP) stops subagents and their commands, bash jobs and MCP servers the way SIGTERM does, instead of leaving the subagents' commands running; restoring the terminal at exit never fails on a hung-up terminal.
- Fixed: a prompt typed and sent with Enter before the interactive screen appears is sent once startup is ready, instead of staying in the editor with a newline. Several Enters send it once; several typed lines become one multi-line prompt.
- Fixed: a subagent that ended while waiting for a sibling's prompt cache could later become that cache's first child for good, so every later child of the same model waited forever and its siblings' reports never arrived. Retried report deliveries no longer send a sibling's held report early, and a report no longer waits on a sibling that stalled or whose run is over.
- Fixed: a second Octocode opening a database that another process is migrating no longer copies the whole file and blocks for 5 s on every call; it reports the database busy until the migration commits. The version 10 move makes the transcript copies durable before dropping the old tables, and a backup is never replaced by an incomplete copy.
- Fixed: a recalled or restored large prompt is sent in full after queued messages, a refused send, a fork or a closed extension dialog put text back in the editor; its `[paste #N …]` marker could be sent as literal text. The external editor opened from an extension's editor and a reopened free-text answer in the ask dialog also get pasted text in full.
- Fixed: keys typed in the same burst after a key that opens a selector or overlay now go to that selector instead of the editor. A prompt queued during startup that you changed after Enter stays in the editor with a status instead of being dropped.
- **File references open in your IDE.** A new `referenceOpener` setting (default `auto`) opens file references and `/diff --editor` in the IDE whose terminal runs Octocode (VS Code, Insiders, VSCodium, Cursor), in the current window and at the referenced line, even when its command is not on PATH; otherwise in a GUI editor found on PATH; otherwise in your terminal editor as before. GUI editors start beside the session instead of taking over the terminal. `editor` keeps the old behaviour; `externalEditor` is now only for prompt text.
- Fixed: Ctrl+G and other prompt edits with VS Code, Zed or Sublime as the prompt editor were lost, because the editor returned at once; `--wait` is now added.
- Long sessions: Octocode's own tool rows (results, reasons, purposes, reports) are no longer re-rendered every frame (a keystroke at 20,000 entries: about 50 ms → under 1 ms). Fullscreen lays out only the rows in view and measures the rest between frames (settling 10.6 s → 3.2 s of CPU), transcript search no longer rebuilds its index on every streamed frame (1.4 s → about 3 ms), the first search key never blocks, dialogs no longer walk the transcript on every redraw, and Ctrl+O expands lazily.
- New setting `terminal.replayRows` (default 5000, `0` = all): in the main screen a redraw after a resize or `fg` writes only the last rows, after one marker row. Only the screen is shortened; the session and what the model sees are unchanged.
- Enter pressed while Octocode starts is no longer refused: the prompt stays in the editor, queued, and is sent once startup is ready. Esc cancels it; editing it keeps you writing.
- Typing: text arriving without bracketed paste no longer slows down with its length (10 KB: about 0.7 s → 20–35 ms), keys are matched without re-parsing key names, a refused prompt and a recalled history entry keep their paste markers, cursor and undo steps (the model still receives the full text), and changing a setting by key (Ctrl+T, Shift+Tab, Ctrl+P) no longer blocks input while the settings file is written.
- Subagents: a finished child's report reaches the parent as soon as it is ready (the fixed 1.5 s batching window is gone); it waits only for a sibling of the same step that has already finished and is assembling its report, and a busy parent reads reports together after its turn. Siblings wait for a shared prompt cache only on models whose cache reads cost less than writes, and a waiting sibling is never judged stalled. A headless run whose children finish while it waits reads all their reports in one turn. Process samples no longer delay start, switches or quitting.
- `/new`, `/resume` and fork keep connected, idle MCP servers whose launch did not change (the first prompt after `/new` no longer waits about 175 ms for a restart); subagents running on their parent's skill inventory start their MCP servers with the session.
- Headless runs and subagents write Node's compile cache while their first request is out instead of at exit (a cold subagent's parent wakes about 0.2 s after it finishes instead of 3.9 s). The interactive mode still writes it at exit.
- `octocode --version` and `octocode --help` print without loading the session code (`--version` in about 0.15 s).
- The screen no longer stalls when another Octocode process writes the agent database: a write retries its start every millisecond within the same wait budget instead of sleeping through SQLite's growing backoff (worst case about 0.5–0.9 s → about 10 ms).
- Credentials kept in the system keychain or as a `!command` are read without blocking the screen; the same command and cache are used. A fresh saved models.dev index is no longer parsed at every session start.
- Fixed: `nativeToolExposure` pins and `mcpExposure: "direct"` were ignored for Octocode's own tools; they now apply when the session starts. Resuming, reloading or forking keeps the native tools the session declared, so the provider's cached prompt still matches.
- Fixed: each session switch in hosts other than the CLI left a credential watcher running; the runtime now releases the services it replaces and its last ones on exit. The startup session sweep no longer parses every transcript (which kept up to tens of MB of session text in memory), and the session picker's cache no longer counts a file once per concurrent listing.
- Syntax grammars beyond the common languages load when a code block first needs one, and the block redraws highlighted; discovery records, new state folders and recorded skill descriptions skip disk flushes they do not need; finding `fd` and `rg` on PATH no longer starts them.
- Long sessions: a turn no longer rebuilds the model context from the whole session branch. The projection is kept and extended as entries are appended, turn-boundary previews reuse it, and context-usage and compaction checks read back from the leaf only as far as they need; turn CPU at 20,000 entries is now close to 1,000 (about 140 → 85 ms per turn; reading the kept projection still grows slowly with the branch).
- Each model request hashes only the request layers that changed and reuses their trace objects, and built-in `context` handlers declare that they only read, so the transcript is no longer deep-copied per request (about 27 → 2 ms per request at 3,500 messages; request bodies and stored traces are byte-identical).
- Fixed: each `/new`, `/resume`, fork or reload left the previous model runtime watching `auth.json`; watchers and availability passes no longer pile up per switch.
- Session start reads only the lines its transcript appended since its last complete history repair, and opening a session whose database copy is behind sends only the appended lines (at 20,000 entries: about 190 → 4 ms and 450 → 4 ms). Changed, rewritten or incomplete transcripts are still read whole.
- The session picker reuses unchanged sessions' listings within a process, and `--session`, `--fork` and `--session-id` read file headers only.
- Resuming, reloading or forking a session keeps the MCP tools it declared, so the provider's cached prompt still matches.
- Clearing old tool results resolves the session output folder once per batch.
- Long sessions no longer slow every frame: containers skip components that did not change, and the main screen processes rows only from the first changed one. At 20,000 entries a keystroke frame dropped from about 28 ms to 0.2 ms in the main screen and from about 8 ms to 0.3 ms in fullscreen; garbage per frame from 25 MB to about 1.4 MB.
- A streamed reply no longer copies the whole transcript store on every token, and after each reply the footer, turn line, spend totals, session catalog row, memory injection and session name read only the entries added since their last read (about 15 ms → 0.25 ms per reply at 20,000 entries; the 36 MB message-text string per reply is gone).
- **Breaking (database schema 10): the transcript copy moves out of `workspaces.db`.** Session entries, transcripts and compaction summaries now live in `transcripts.db` next to it; `workspaces.db` keeps coordination and global data (on a real 122 MB database: 3.7 MB after the move). The move is verified per session, resumes after a crash, and compacts the old file. An older Octocode refuses migrated files. Each database writer checkpoints its own file, and the write-ahead log shrinks once writes stop.
- Purging a workspace now also removes its agent runs (purge failed with "FOREIGN KEY constraint failed" when a workspace had runs).
- Octocode's own test runs can no longer open your real agent database: they run in their own home, and any process they start that resolves the real database is refused and fails the run. Octocode started from your own test harness is not affected.
- A replaced or disposed session no longer reports archive errors through its stale context (an unhandled "extension ctx is stale" rejection); the archive stops following database commits once its session is gone.
- Compaction no longer runs for many minutes: compaction and branch summaries cap their output at 32,768 tokens and think at most at `low` (the cache-shared summary keeps the session's thinking so it reuses the cached prefix). The status line shows elapsed time and tokens received, and an attempt that receives nothing for `httpIdleTimeoutMs` is retried by the retry policy, which the cache-shared and standalone summaries now honor.
- Another Octocode process holding the database no longer freezes the screen (an event-loop stall of up to 6 s under a held lock is now under 16 ms): memory and session bookkeeping go through the database writer, and team writes retry off the screen's thread. Process liveness checks on timers and exit paths no longer run `ps` on the main thread; auth, provider-toggle and git-branch changes are picked up by file watchers instead of polling every second; the agents.txt view is written asynchronously.
- Ctrl+Z no longer stops subagents, running bash commands or background jobs (a stopped subagent could hold the shared database lock). A command that takes over the terminal starts only after Octocode has restored it, and extension commands run in their own session, outside the terminal.
- Fullscreen scrolling: a wheel notch scrolls 3 lines on every terminal (Terminal.app moved 1), events read together no longer jump, and a frame moves at most 24 lines. Pointer frames keep the display's 60 Hz from frame start, also while large output streams. Spinners and shimmer hold still while you scroll. Mouse modes are restored after focus-in, resize or `SIGCONT`, and idle pointer movement is not tracked unless the scrollbar shows. An input listener that throws is reported and kept, so scrolling no longer dies; the wheel keeps scrolling the transcript during a full repaint; the first scroll after a resize no longer measures the whole transcript.
- Deferred and compact MCP tool declarations list nested field names and types (for example `queries[].ranges[].startLine`), without descriptions, at most 32 per object.
- Scrolling keeps up with the hand on macOS terminals: a fast wheel or trackpad flick moves several lines per event (240 events moved 239 rows, now about 700), slow scrolling still moves one line, and every wheel event inside one frame becomes one scroll. `fullscreenWheelScrollLines` still sets a fixed count.
- Without confirmed synchronized output (Terminal.app answers no query for it), frames are paced to the 60 Hz a terminal paints, each frame is one write, and the scrollbar no longer jumps while the view scrolls. Synchronized output is used only when the terminal confirms it.
- Regular (non-fullscreen) mode no longer replays the whole transcript and clears scrollback when a row above the screen changes or on ctrl+o (435 KB down to a few hundred bytes); expanding tool rows and large tool previews render faster; the first Shift+Enter check no longer delays Enter by about 30 ms.
- A terminal that stops reading no longer grows the output queue without bound: past `fullscreenFrameQueueLimitKiB` (default 512, 0 turns it off) stale frames are dropped and the screen is repainted whole once it reads again; mode, restore and transcript bytes are never dropped. A crash also clears the terminal's "working" status, and a `SIGTSTP` sent by another process suspends like Ctrl+Z and restores the terminal.
- Regular mode no longer writes the whole transcript a second time at startup unless a code block's language has just loaded (a large session wrote 232 KB with a full clear, now 104 KB without one), and tool rows reuse their drawn lines across redraws and ctrl+o toggles.
- A models.dev refresh after startup no longer sends a false "the user changed models or providers" routing notice (it happened whenever the saved index was missing or more than a day old), and Claude Code as the session's model never receives routing notices.
- Less memory and copying per turn: request traces share unchanged parts and are no longer copied for every request (live traces 22 MB down to 1.6 MB on a long session); a finished `bash` result's full output for programmatic callers stays in its saved file until read; one reader serves every message's saved content; a long `!` output is shown by its ends without reading it whole.
- New `--rpc-lean-events`: RPC sends each message and tool result whole once instead of repeating it in every end event (about 18 times less JSON for a large tool output); subagents use it, and the default events are unchanged. A database mirror that fell behind continues from its last stored row. ACP no longer crashes with `EPIPE` when its client disconnects.
- The bundled Octocode research server follows the deferred default: its tools are declared in full once this folder has used them, so a first request is about 44% smaller (`"exposure": "direct"` in `mcp.json` keeps them full). Subagents of the general, researcher, reviewer and implementer roles send the same tool list and share its cache.
- Octocode no longer ships rewritten descriptions for any MCP server: the browser server's instructions, tool descriptions and field notes now reach the model in the server's own words in `compact` mode too (the default `declared` mode already sent them verbatim). `octocode mcp compact preset` is removed; overrides you stored yourself with `octocode mcp compact apply` keep working, and a `compact` file an earlier release wrote with shipped overrides is rendered again once.
- A deferred MCP tool is declared in full after its first call in a session on models that can replace a tool's definition in place (Anthropic models with mid-conversation tool changes, OpenAI Responses models with additional tools). The tool list and instructions sent at the session's start are not rewritten; on other models the tool stays deferred and a rejected call still returns its schema.
- The web Settings page has a Tools panel: a table for the native tools and one per enabled MCP server with each tool's state (direct, deferred, hidden), what decided it (a pin, the server's `exposure`, use in the last 24 hours, the default) and a pin control. A pin is saved as the tool's `toolExposure` entry in `mcp.json` or under `nativeToolExposure` in `settings.json`, globally or for a trusted workspace, and applies from the next session. Only the page opened from the terminal can read or change it.
- The session database mirror and archive views are written by a background worker, so a busy database no longer freezes typing, timers or the screen while a session saves. The session file itself is still written before a message counts as saved. Archive history, `/resume` listings and fork lineage wait briefly for the latest rows, and an `archive` result says so when it had to answer without them.
- A package that `/reload` or a session switch installs (a missing configured package, an unpinned git source) no longer takes over the terminal while the interface runs: npm and git write to stderr and read no input, and the screen stays responsive. Outside the interface they still use the terminal as before.
- Cancelling a run no longer waits for an extension or SDK listener that is stuck on a streaming update (`message_update`, `tool_execution_update`). Every other event, `message_end` and `agent_end` included, is still awaited in order, so the aborted message is saved before the next prompt.
- Long transcripts redraw faster while a reply streams: only the rows after the changed message are rebuilt. Several images in one prompt are prepared three at a time instead of one after another.
- Fullscreen mode draws the first frame and each window resize from the visible rows only, even with long transcripts (about 2 ms at 2,000 messages, down from about 150–210 ms); the rest is measured over the next frames, and search, selection and scrolling still cover the whole transcript. A resize repaints right away, then again once the drag pauses (at least every 250 ms), instead of at every step.
- Typing and streaming in regular (non-fullscreen) mode no longer slow down as the transcript grows (about 9 ms per key at 2,000 messages, now about 2 ms): cursor and image bookkeeping reuses unchanged rows from the last frame.
- `@` file completion no longer holds typed keys in large folders: ranking runs in chunks that yield to input and stop when you keep typing, it keeps only the best 50 matches, and it waits 60 ms (was 20 ms) after the last key.
- Streaming costs about 5× less CPU per token: appending stays on the fast path when the provider runs ahead of delivered updates, web and ACP views get append-only deltas, and with no view connected nothing is redacted, encoded or kept for replay (a view that connects later starts from a snapshot). With Mermaid rendering on, text without a Mermaid fence is no longer re-parsed on every chunk, and drawn diagrams are reused.
- A run ends sooner: the session record (`SESSION.md`) is written in the background, only when it changed and without fsync (shutdown waits for it); the skill catalog is validated once per reload instead of before every request; the session mirror reuses the workspace identity while nothing above the cwd changed; `!command` API keys and headers refresh in the background during their last cached minute.
- `file` tool writes flush the edited file but not its directory, and checkpoint blobs (digest-checked on `/rewind`) are not flushed, saving 5–10 ms per change.
- Session appends sync to disk once the session pauses (250 ms, at most 1 s) and at exit, instead of 20 ms after each append. Rewriting a session file, or rebuilding its database mirror, prepares the content before taking the session lock, so the lock is held for milliseconds instead of 80–140 ms on large sessions.
- The database writer saves only the transcript rows that differ and splits large saves into short steps, so the main thread no longer waits about 65 ms for it; the cleanup sweep's checkpoint no longer waits up to a second for other connections. The archive retention sweep rereads only session files that changed since their last complete repair and parses only lines that can hold a compaction (later sweeps about 60 ms instead of about 800 ms).
- Parallel subagents that share a prompt prefix start together; only their first model request waits for the first sibling's reply. A background subagent's report reaches the parent at once when no other background subagent is still running, instead of after a fixed 1.5 s. Settings loads no longer wait on the settings file lock.
- The Node bundle ships the database writer as its own small worker file (`db-writer-worker.js`), so each process's writer thread no longer loads the whole bundle (about 290 ms and 230 MB less per process, subagents included). Running from source turns on Node's compile cache.
- Session files are about 45% smaller: each request trace, system prompt part, tool declaration and duplicated `bash` output is stored once per file and referred back to (the largest session went from 19.7 MB to 5.8 MB and opens three times faster). Every file stays self-contained, old files load unchanged, and a file written by this version cannot be read by an older release. A `bash` output that is one huge line shows its last 20 KB instead of nothing; the full line stays in the saved output.
- `mcpExposure` defaults to `"recent"`: MCP tools and `web`, `archive`, `models` and `backlogPlan` are declared with their description and top-level fields until this folder uses them, and again after 24 hours unused; a newly used tool is added at the end of the prompt, so the cache prefix is kept. `"mcpExposure": "direct"` restores full declarations.
- A subagent's history cache tier follows its task when the coordinator does not set `cache`: long when it lingers, is resumed, thinks at `high` or above, or has a large request budget; short otherwise (the long tier costs more to write, and children rarely pause). A retention you configured still wins. Agents of different roles share the cached tool prefix through a breakpoint after the shared tools (Anthropic). Each cache breakpoint's lifetime is recorded, so the profiler attributes a miss to the right tier.
- Listener and event handler failures inside the agent appear in the session's diagnostics (the chat, print-mode stderr, RPC `extension_error`) instead of raw stderr drawn over the screen; a session with nothing listening still prints them. `/configuration` shows which copy of a same-named skill loads and marks the others as shadowed.
- Old tool results are cleared while the cache is warm when re-sending them costs more than one cache rewrite, and on every rewrite that happens anyway. Read-only `bash` results can be cleared too; a full copy is saved first.
- `archive` checks its arguments first and repairs only transcripts that changed, so a call takes tens of milliseconds instead of about two seconds. A regex `query` searches every record, one cursor continues every result (`page` is gone), the default list is compact, and `request` replaces `line` for a request profile.
- Compaction: the modified-files list includes `bash` edits and subagents' edits and says whose they are; an automatic compaction that frees nothing is not committed; after a switch to a smaller model it keeps a shorter recent tail before summarizing, and when nothing fits it stops at once with what to do instead of sending a request larger than the window.
- Memory recall searches on user prompts only: a wake from a notice or a report gets unseen pinned notes and nothing else, and the injected text stays within its 2,400-character budget.
- Subagents: a crashed child's running `bash` commands are stopped; a crashed batch entry names its goal and last tool call; the resume note keeps unanswered calls and the last request whole and names the stopped children of an unanswered `agent` call. The loop guard's refusal is recorded in `/permissions log`. A checkpoint is no longer reused from a zeroed blob left by a crash.
- A user `!` command runs through one operation in every mode and is refused when a hook that checks it fails. `RpcClient.start()` waits for `rpc_ready`. The `pi` key of an extension's `package.json` is no longer read. Failures that are not `Error` objects show their text instead of "Unknown error".
- `/web` opens the user-level web daemon by default; the session's own server opens only when the daemon cannot start or the session cannot attach, after a warning. `OCTOCODE_WEB_DAEMON` is removed. A session's Settings → Tools panel on the daemon page shows what that running session declares, board edits there refresh the footer counts of that repository's sessions, and `/backlog` and `/backlog web` open the same page as `/web backlogs`.
- Web page: streaming text updates once per animation frame; every link it makes clickable is `http` or `https` without credentials; a non-JSON error shows the action's own message; trace export times out after 15 seconds and asks you to sign in when the link expired; the `Bearer` scheme is accepted in any letter case.
- On Windows, `/backlog html` and the default-browser fallback open through the system URL handler instead of `cmd /c start`, so `%VAR%`, `&` or `^` in a path is never re-parsed. `octocode mcp login` says when the browser could not open. Paths show the home folder as `~` the same way everywhere, the home folder itself included.
- Telemetry span and metric names are `octocode.ai.*` (were `pi.ai.*`). A malformed OpenAI stream frame names the API and quotes the frame with credentials removed. The standalone `octocode-ai` login command is removed: it wrote credentials to `auth.json` in the current folder.
- Security: a `PermissionRequest` hook's plain allow no longer skips a provenance hit or a hook ask; those still need a person, and headless they are refused. A Claude source ask is still the hook's to answer. The per-session `/web` page now sends the same hash-based Content-Security-Policy header as the web daemon (no inline script runs beyond its own and the Mermaid loader) and `nosniff`.
- Mermaid diagrams in the terminal show their theme colours. Extension Markdown transformers run before Mermaid diagrams are drawn, so they receive the Mermaid source; their output is still sanitized.
- The database writer opens its connection again for a later command when the first open failed, instead of failing every command for the rest of the process; recording the same fork edge twice (a retry after a lost acknowledgement) no longer fails.
- Codex errors carry the provider's `Retry-After`, so session retries wait as long as the provider asked. Anthropic closes the response stream when an `onResponse` hook fails. Google and Vertex call `onResponse` with the response headers, like the other built-in providers.
- In fullscreen mode, a scroll key is no longer lost when a transcript entry that fails to render is measured for the first time; the entry shows its render-error fallback and the error is reported once.
- MCP servers start once per session: startup connections wait until the session's skills are loaded, or start sooner when the first prompt or a hook needs a server (the built-in server used to be started, killed and started again). The GitHub sign-in check runs `octocode auth status --json` once instead of asking the CLI's help first.
- The system prompt now reaches providers with explicit cache breakpoints (Anthropic, Bedrock, OpenRouter with Anthropic-format markers, OpenAI and Azure explicit mode) as three instruction blocks instead of two: the working directory, the date, the plan-mode constraint and MCP status form a last block without a breakpoint, and the working directory moved from before the policy to the start of that block. A new day or a different MCP status at session start no longer rewrites the cached project block. **This changes the cached prefix once for every user: the first request after upgrading writes the instruction cache again**, and sessions saved earlier keep their stored section order. Anthropic requests still carry at most four breakpoints.
- **Breaking: the `steps` tool is removed.** It was off by default; naming it in `defaultTools`, `--tools` or a profile's `tools:` now gets the unknown-tool warning, and a call to it is refused with one sentence saying to keep steps in the item's plan (`backlogPlan` `edit`) and progress in `backlog` `note`. Stored steps are kept: `backlog get`, the resume brief, `/backlog` and the web board still show them, and you finish or drop them on the board, which an item with open steps still requires before it is done or closed. Stored sessions that recorded `steps` calls open and render as before.
- A subagent runs none of your hooks by default, so a deny hook does not cover delegated work unless hooks are turned on for the child. Three modes: `off`, `decisions` (your `PreToolUse` and `PermissionRequest` hooks run and only their deny or ask takes effect; a `PermissionRequest` allow grants nothing, and a hook that fails or times out fails open unless it sets `failClosed`) and `all`. A profile's `hooks` front matter takes `false`/`off`, `decisions` or `true`/`all`, and the coordinator can set `hooks` per task on the `agent` tool; a profile's `hooks: false` forbids them whatever the task asks.
- A subagent receives pinned memories of kind `preference` before its prompt, within the same 1,200-character pinned budget as the main session. Pinned facts, decisions and other kinds are still not injected into a subagent, and a lean child still gets no memory notes.
- A subagent's history cache tier is chosen per task, because a long cache write costs more (on Anthropic 2× the input price for 1 hour against 1.25× for 5 minutes): the `agent` tool's new `cache` field takes `short` or `long`, and without it a background, lingering, resumed, isolated or high-thinking task gets `long` and a quick foreground one `short`. Instruction blocks keep the session's tier, and a `cacheRetention` you set in settings, a provider or model entry, or `OCTOCODE_CACHE_RETENTION` still wins.
- A subagent whose report names no outcome is asked once for the word (`done`, `partial`, `blocked` or `failed`), at the cost of one more request; an answer that names none is recorded as `partial`. The report itself is unchanged, and `/agents stats` still counts only reports that led with the word.
- Delegated cost is easier to see and nothing is refused for it: a `coordinate` `grant` result names what the child has cost so far, the line saying a finished run stays reachable names the requests and cost of that run, and a report ends with one line when the children's cost passes a new whole multiple of the session's own.
- A conversation too large for the summarizer is summarized in two parts, the older part first and then the rest on top of it, instead of leaving the oldest messages out.
- The cleanup at session start keeps an aged output or bash log that the session's latest summary names; it goes with the session.
- `/context` and `octocode context check` warn when one MCP server's instructions, or the project's context files together, take over 1% of the context window. Nothing is cut.

- The `backlog` tool is two tools. `backlog` works one item (`get`, `claim`, `note`, `done`, `close`) and is what a subagent with an item gets. `backlogPlan` plans and triages (`add`, `edit`, `list`): `add` and `edit` take `items`, one typed entry per item, and `list` filters under names of its own (`underEpic`, `anyTag`, `touchingPaths`, `inTitle`, `ofType`, `dependingOn`, `priorityAtLeast`, `derivedFrom`). A `backlog` call with `op` `list`, `add` or `update` is refused with the tool and op to use; stored sessions still show their old calls. Under `mcpExposure` `"recent"`, `backlogPlan` is deferred until the working directory uses it. `defaultTools`, `--tools` and profiles that should plan need `backlogPlan` beside `backlog`.
- A completion whose `verification` sentence names no result is recorded as `not_stated`, no longer as passed, and the result says so; start the sentence with passed, failed, not run or not applicable. `backlog` `get` and `backlogPlan` `list` run beside other reads. A version conflict answers "changed elsewhere (now version n): get it, then retry", and a refused field or state names the valid ones.
- Saved notes have their own tool, `memory` (`search`, `get`, `list`, `set`, `delete`; a subagent reads only). `archive` keeps session history, compaction summaries and diagnostics, and its fields no longer change meaning with the source. An `archive` call that still names memories (`op: "set"` or `"delete"`, `source: "memories"`, an `M<n>` id) is refused with the `memory` call to make; stored sessions that recorded such calls still open. Scopes, limits, pinning and automatic recall are unchanged. A profile that lists tools keeps `memory` the way it keeps `archive`. See [memory](docs/memory.md).
- A `memory` regex search (`query`) tests every note of the scope instead of the newest page. An `archive` result that stopped early gives one cursor for its records and its session history, and a paged `archive get` ends with its page number and how to read the next. In a subagent `archive` no longer declares the diagnostics (`events`, `profile`, `errors`).
- `timer` is simpler: `until` no longer takes `file` or `port`, since a `command` covers both (`test -e path`, `nc -z localhost 3000`). A call that names one is refused with its command form, and a timer stored with one ends `failed` with the same note at its next check. A `lean` subagent no longer gets `timer` unless its profile's `tools` name it.
- One protocol between agents: `agent` type `message`, `to` a name, also reaches another Octocode process by its process name, with no shell and no connection. A session's name is in its prompt, `coordinate list` shows the other sessions with folder and busy state, and each message says who it is from and how to answer.
- A session in a linked worktree that has finished sends `to` `coordinator`: the session in the main checkout, which reviews and merges with `coordinate merge` and answers. It asks its user in every mode, `full` included, and refuses uncommitted work, a held path or a conflict with the reason to send back. No coordinator or several: told plainly, nothing sent. `/worktree merge <branch>` is the typed form.
- `git merge`, `git pull`, `git rebase`, `git cherry-pick` and `git am` through `bash` ask like `coordinate merge` when they act on the main checkout while it is on the default branch, in every mode, `full` included: the same dialog and one session grant. A feature branch, a linked worktree's own branch, `--abort` and `--continue`, and a command you type with `!` ask nothing. With no one to ask it is refused and nothing changes. It fails open, and a script can still run `git merge`: [Landing through the shell](docs/permissions.md#landing-through-the-shell).
- A session in a deep home no longer leaves `octocode-<uid>-*` socket folders in the temp directory after a kill. A start with the API on removes those whose owner is gone, from any home, and never a live session's.
- Receiving an external message is a permission class, `message.external`. `full` takes it unasked. `manual`, `workspace` and plan show who sent it and ask: this message, this process or all processes for the session, or deny. A refusal reaches the sender, `/permissions grants clear messages` revokes, and the audit names the process. Accepting a message never widens what its tools may do.

- A turn the local session API starts runs in the session's own mode by default, so a remote agent is never stuck on a prompt. Setting the global `sessionApiTurnPermission` to `workspace` holds API-started turns, and messages that steer a running turn, to `workspace` even when the session is in `full`: the user is asked about the message, and tool calls `workspace` asks about ask or are refused when nobody can answer. The caller name is recorded as unverified (`callerVerified: false`) in the `octocode-external` entry and `external.message` event.
- Every top-level session is reachable by default: it serves the local session API on an owner-only Unix socket with no setup. `OCTOCODE_API=1` is gone; the `sessionApi` setting and `/api off` turn it off. Loopback HTTP stays opt-in (`OCTOCODE_API_HTTP`, `/api on http`), and a Windows session, which has no owner-only socket here, starts none unless asked. A session whose API cannot start warns and carries on.
- An API message reaches the model marked as external: another process on this machine, not the user, with what the caller says it is, in the sender-proof fence. It can make requests and never grants approval. The terminal shows `✉ external` with the caller; RPC events carry the same facts at `details.external` and ACP at `_meta["octocode/external"]`. A pending permission dialog or question still waits for its owner.
- `octocode-api send` names its caller, from a session's shell that session, and the receiver is told how to reply. `--to`, `/agents external connect octocode` and the `agent` tool's `instanceId` take the process name from `/processes` (`octocode-main-c0ea9f3e`), its id, the session ID or the pid; a bad or ambiguous one lists what would work. `octocode-api list` shows name, id, pid, cwd and whether it is busy, and clears a dead record even when its pid was reused. `send` refuses the caller's own session. `/processes` shows each process's name and API id. Attaching to a running instance no longer needs its folder.
- ACP: closing an unknown session succeeds and cancelling one is ignored; `-32002` names the session in `data.sessionId`; an untrusted folder is now `-31000` (`-32002` said the resource did not exist); `$/cancel_request` on a prompt ends it `cancelled` (it did nothing); tool calls carry `name` and `kind`; a worker that cannot start says why. The broker names itself `octocode-acp-<pid>`.

- `compact` works in a headless run: `octocode -p` waits for the compaction it asked for and answers from the turn that resumes, instead of cancelling it and printing the status line. If the compaction cannot run, the run goes on without it.
- A headless Chrome that a browser subagent leaves open stops when the top session shuts down; a visible one stays. A follow-up in the same session still reuses it.
- A message to a subagent that has not joined yet says it is still starting, not that no such agent is alive.
- MCP signatures no longer offer a field on an operation whose server refuses it there (`lspSearch` `symbolName` and `line` on `documentSymbols`, `ghGetHistoryItem` `number` on `commit`).

- Reports and background job results waiting when a parent would stop now arrive together, as one turn, so a final answer is not written with a report still due. A setting of `followUpMode` still decides for your own queued messages.
- When a message resumes a subagent, its unread earlier report says that its waiting and unanswered lines are out of date.
- `/quit` asks first while a reply, bash job, background subagent or external prompt is running, like `/new`. `/agents kill` asks first too.
- `/agents tell <agent> #<message> <text>` answers that question and closes it. `askUser` can show a child's question word for word (`forward`).
- A child's report says when it edited files after its last passing verification.
- `/llama` warns when a model is larger than the free memory. The default number of subagents follows the machine (at most 6); `OCTOCODE_MAX_SUBAGENTS` still wins.
- A read-only role's start prompt no longer says it may edit files. A headless session's prompt no longer tells the model to use `askUser`.
- A tool call with `cursor` inside `queries` is told the correct form.
- `api.exec` reports a signal exit as non-zero, keeps a spawn error's text and really forces a process that ignores SIGTERM.
- Regular terminal mode no longer re-finishes every line each frame. Native commands are advertised over ACP. `OCTOCODE_TIMING` records CPU per phase. Unused memories rank lower after 90 days.

- A running subagent that has exchanged no message with its parent for `subagents.checkInSeconds` (default 300, `0` off) is asked by its own harness whether it needs something. The ping joins a request the child was about to make and costs the parent no model turn. A foreground child is told to finish with `blocked`, since its parent reads messages only with its report.
- `coordinate list` shows a running child's last output and the questions waiting on its parent.
- A parent is no longer told its question went unanswered while the child that read it is still filing the report that answers it, and a foreground report now closes such questions too.
- A report that arrives during the parent's last reply no longer costs a parent request for the notice saying it follows.
- The request budget's steer tells a child where the run stops and to finish the check in progress, instead of "Finish now"; a child resumed past its soft limit does the task it was resumed for. Children were stopping at the soft limit with the hard limit's requests unused, and a resumed one returned after a single request.
- A subagent near its request budget now talks to its parent instead of running on or stopping cold. The steer names the requests used, the soft limit and where the run stops; a background child asks its parent for more in a message and keeps working, and a foreground child says in its report what is left and how much more it needs. The parent adds requests to a running child with `agent` type `coordinate`, action `grant` (`subagent`, `requests`), for this run only, and `coordinate list` shows a child's requests against its limit. No answer changes nothing: the child stops at the hard limit with its partial work.
- Resuming a subagent at or past its soft limit gives it a whole allowance again; at the hard limit it used to return `partial` without running. A budget stop's report says how to resume the child. A peer's message that the parent's process relays is not a grant: such a resume stays within the limits the child had.
- A message to a finished child no longer claims its report already arrived while that report still waits for the turn to end.

- Plan mode lets its documented native reads run: `bash` read-only commands, `askUser`, `archive`, `skill`, `web` and the `mcp` tool's `list`, `tools` and `restart`. A lost tool owner refused them all.
- SIGTERM or SIGINT now ends a headless run that is holding for background work, and stops its children; a second signal exits at once.
- `--exclude-tools` and `--no-mcp` now bind subagents. `--tools` stays the session's own allowlist.
- A headless run the loop guard ends says why on stderr and exits 1, and a failed command exits 1 (RPC answers `success: false`). The "Extension error" prefix is gone.
- A background job stopped at run end no longer starts a turn that replaces the answer.
- `@octocodeai/octocodecode` is now the only package published to npm. The other workspaces are private and compile into one bundle file, `dist/bundle/octocode.js`, so an install no longer pulls them or their dependencies.
- **Breaking: the package no longer ships TypeScript declarations.** The JavaScript exports `.`, `./rpc-entry`, `./mcp` and `./mcp/oauth` are unchanged.
- **Breaking: the `./mcp/testing` subpath is gone, and the package root no longer exports the in-memory MCP transport.** It was a test helper.
- The package includes the project documentation under `docs/project/`, its MIT `LICENSE` and `dist/licenses/THIRD_PARTY_NOTICES.md`, which lists every third-party package compiled into the bundle with its license text.
- Unified saved memory and lifecycle retrieval under `archive`; new notes default to workspace scope while legacy project/global notes and M IDs remain. `/memory` remains available.
- Added durable agent events and complete compaction summaries in the agent database, with a generated, database-bound `.octocode/agents.txt` containing the latest 50 events.
- Archive detail retention now measures the existing cleanup duration from committed compaction time and preserves summaries and original transcripts. Unknown legacy timestamps prevent expiry; expired copies are not rebuilt.

- Claude-compatible plugin marketplaces. `octocode marketplace add|list|update|remove` registers a marketplace (a folder, `owner/repo[@ref]` or a git URL with `.claude-plugin/marketplace.json`) in the new global-only `marketplaces` setting, and `octocode plugin install|update|remove <plugin@marketplace>` manages its plugins (`/plugins install|update|remove` inside a session). Git sources are fetched by a shallow clone with no submodules, LFS, repository hooks or remote helpers, only https, ssh, git and file transports, a timeout, and no credentials in the URL; the plugin is copied to `plugins/cache/<marketplace>/<plugin>/<sha>/` and the `plugins` entry records `source: {marketplace, plugin, sha}`. Installing approves the plugin's hooks and MCP servers (a prompt, or `--yes` without a terminal); an update that changes them asks again and exits 1 without `--yes`. `npm`, `archive` and `command` plugin sources are refused. See [marketplaces](docs/plugins.md#marketplaces).
- Claude plugin agents are now subagent profiles. Each `.md` file in a plugin's `agents/` folder (searched recursively), or in the manifest `agents` list, can be started by the `agent` tool as `<plugin>:<agent>`; subfolders are part of the name (`my-plugin:review:security`), as in Claude Code. A plugin agent never replaces a bundled, user or project profile, loads only for an enabled plugin (project plugins in a trusted folder), and carries over `description`, `model`, `maxTurns`, `skills`, `tools` and `disallowedTools` (an agent without a file-writing tool is read-only); `hooks`, `mcpServers`, `permissionMode` and the other fields with no equivalent are reported in a startup notice and ignored. The startup screen and `/config` list plugin agents with source `plugin <name>`. `agents` is no longer in the list of plugin components Octocode does not load. See [plugin agents](docs/plugins.md#plugin-agents).
- The startup screen shows the loaded context and where each item came from. One row per kind (context files, skills, agents, models, MCP servers, hooks, plugins, prompts, themes, keybindings, settings) gives the count and the sources (`octocode global`, `octocode project`, `pi global`, `pi project`, `plugin <name>`, `builtin`, `command line`, `settings path`) and, when it fits, what does not apply: shadowed Pi copies, project items in a folder that is not trusted, and disabled servers. `ctrl+o` lists every item with its path, and a `(ctrl+o to expand)` hint shows while anything is collapsed. Pi extensions and `hooks/` are one "Not loaded" row naming each file with the way to convert it to `hooks.json` or a plugin; the same warning no longer repeats in the Warnings row, the extension-issues block or the startup notice lines of the interactive mode. The first start that finds Pi items prints a one-line notice naming what it found, once (recorded in `pi-notice.json` in the agent directory). The new read-only `/config` command prints the same snapshot as text, in RPC and print modes too; it refreshes on `/reload` or a new session.
- Settings from Pi are now a read-only layer. A save writes only Octocode's own values: before, `~/.pi/agent/settings.json` values could be copied into the Octocode settings file the first time any setting was saved. With the default home and in a trusted folder, `.pi/settings.json` is read too, between the Pi global file and the Octocode global file (Pi global < Pi project < Octocode global < Octocode project). A Pi settings file that does not parse is a startup warning instead of a settings load error. `models.json`, `settings.json`, subagent profiles, hook files, plugins and MCP servers are listed through the configuration-discovery service with their source; an MCP `enabled` or `exposure` entry is listed as a control-only override apart from definitions.
- Pi compatibility covers more files. With the default home, Octocode also reads a global `AGENTS.md`, `SYSTEM.md`, `APPEND_SYSTEM.md` and `keybindings.json` from `~/.pi/agent/` (its own files win), and in a trusted folder `.pi/skills`, `.pi/prompts`, `.pi/themes`, `.pi/SYSTEM.md` and `.pi/APPEND_SYSTEM.md`. Pi TypeScript extensions and hooks are listed at startup as "Pi extension, not loaded" and never run. Discovery of these folders now goes through one `ConfigDiscovery` service that records where each item came from and which copy a same-named item shadows. `OCTOCODE_HOME` subagent profiles are read from that home only; they previously also read `~/.octocode/octocodecode/agents`.
- **Breaking: the one-time converters are removed.** `octocode migrate` no longer exists (it is now treated like any other first word of a prompt) and nothing runs at startup to convert old files: credentials in `oauth.json` or the `apiKeys` of `settings.json`, sessions left in the agent root, `commands/` folders, `tools/` binaries and old keybinding names are no longer moved or rewritten. Keybinding names that predate the `tui.*` and `app.*` ids (`cursorUp`, `expandTools`, …) are no longer mapped on load. The folder-trust import of `trust.json` and `pi-trust.json` is gone: a folder trusted only there asks again once (`octocode trust add <path>` records it). Backlog items of type `task` are no longer rewritten to `feature` when the agent database opens. Readers of stored formats stay: session file versions, the transcript envelope and MCP OAuth credentials.
- Hooks follow Claude Code's contract more closely. Native `hooks.json` `SessionEnd` handlers now run when a session ends (they were rejected before), and the SessionEnd timeout budget counts native and plugin hooks, not only Claude-format settings hooks. A Claude hook that exits 2 with a JSON blocking decision uses that decision's reason instead of stderr; a Claude `Stop` hook whose script is missing no longer blocks; `shell` (`bash` or `powershell`) is accepted on Claude command hooks; a hook with `if` is skipped with an explicit diagnostic instead of running unfiltered.
- **Breaking: plugin hooks and MCP servers no longer need a copied fingerprint.** Adding or enabling a plugin approves them. The `hooksFingerprint` and `mcpFingerprint` settings are removed; a leftover value in a `plugins` entry is ignored and never stops the plugin from loading.
- The `/backlog tui` board fits its rows to the terminal width (aligned columns, wide characters never split, the lowest-priority columns drop first), shows blocked and stale marks and an epic's progress, colours state and priority with theme colours, and re-reads the database once a second so an item another session adds appears while it is open. The footer and the board now count the same way: an epic counts once by the state its items give it, so the footer's "to triage" no longer includes epics, and the backlog tool's "await triage" line no longer counts a stored-backlog epic. Transcript results of the `backlog` tool are coloured; their text is unchanged. The `/backlog` description now reads "Open the live backlog board; tui for terminal".
- A message typed in the terminal or /web that names an image file (an absolute, `~/` or `./` path, a quoted path with spaces such as a pasted macOS screenshot, a drag-and-drop path or a `file://` URL) now sends the image to the model with the text, so a pasted path or a `Ctrl+V` clipboard image reaches the model after startup. Up to 8 images attach per message; see [attach images by path](docs/models.md#attach-images-by-path).
- Settings files with a root key Octocode does not read now produce a warning at startup, naming the key and file. The keys stay in the file and loading does not fail.
- **Breaking: compatibility aliases are removed.** `--approve` (use `--trust`) is an unknown option; the `task` tool name no longer selects `steps` in `defaultTools`, `--tools` or profiles; the backlog protocol no longer accepts `type: "task"` or `why`; the MCP exposure values `auto`, `deferred`, `codemode` and `codemode-deferred` get the plain enum error; and the named replacement hints for removed settings and tools are gone (the generic unknown-key warning stays).
- The shared contracts workspace package `@octocodeai/octocode-contacts` (`packages/contacts`) is renamed `@octocodeai/octocode-contracts` (`packages/contracts`). Imports of the old package name no longer resolve.
- **Breaking: the package root now exports only the CLI and RPC.** Removed from `@octocodeai/octocodecode`: the SDK (`createAgentSession` and its option and result types), the runtime and services (`AgentSessionRuntime`, `createAgentSessionRuntime`, `createAgentSessionServices`, `createAgentSessionFromServices` and their types), `AgentSession`, `SessionManager`, `SettingsManager`, `ModelRegistry`, `ModelRuntime`, `DefaultResourceLoader` and the other session, settings, compaction, skills and tool exports, `defineTool`, `createBashTool` and `createBashToolDefinition`, `ExtensionRunner`, `discoverAndLoadExtensions`, every `Extension*` type, `createMcpExtension` and `octocodePreset`, the interactive components and theme utilities, `InteractiveMode`, `ApplicationService`, `getShellConfig`, `parseArgs`, `getExamplesPath`, and the trust exports `ProjectTrustStore` and `hasTrustRequiringProjectResources`. Kept: `main`, `VERSION`, `runRpcMode`, `runPrintMode`, `RpcClient` with its option, command, event and response types (including the `RpcExtensionUI*` types and the `extension_ui_*` wire messages), and the `./rpc-entry`, `./mcp`, `./mcp/oauth` and `./mcp/testing` subpaths. Programs that embed Octocode run it as a child process through `octocode --mode rpc` or `RpcClient`.
- Removed the documentation for the SDK and for writing extensions (`docs/sdk.md`, `docs/extensions.md`, `docs/extension-contracts.md`) and the `examples/` folder, which is no longer published. User code extensions are removed: `-e <path>` and `--extension <path>` exit with status 2, `--no-extensions` and `-e builtin:<id>` are accepted for compatibility, and code files listed in the `extensions` setting or found in an `extensions` folder are ignored with a warning and never run. Add behaviour with plugins and hooks (see PLUGINS.md).
- Every agent with MCP has one `<mcps>` section that lists each enabled server with its own instructions and, for each tool enabled for that agent, its description and schema; a server that is not connected yet says so in one line. Tools the TypeScript form cannot express faithfully, and every tool when `mcpPresentation` is `json`, are shown as their description and the server's JSON Schema. Provider declarations of MCP tools stay thin in both modes.
- Octocode's own prompt text no longer tells the model when or how to use a particular MCP server; each server describes itself through its instructions, tool descriptions and schemas.
