# Model operations

Typed, host-free clients for operations beyond chat and images. Every function takes an `OperationClientConfig` plus a request and returns parsed, validated data. Nothing returns synthetic results: a failure always throws `OperationError`.

## Shared behavior

| Setting             | Meaning                                                                                      | Default        |
| ------------------- | -------------------------------------------------------------------------------------------- | -------------- |
| `baseUrl`           | Service root (`http`/`https` only)                                                           | required       |
| `apiKey`, `auth`    | Key sent as `Authorization: Bearer …`; `auth: { header, scheme: "" }` sends a raw key header | none           |
| `headers`           | Extra headers                                                                                | none           |
| `fetch`             | Injectable fetch                                                                             | global `fetch` |
| `timeoutMs`         | Per-call timeout (also per call)                                                             | 60 000         |
| `maxResponseBytes`  | Cap on any response body (also per call)                                                     | 32 MiB         |
| `signal` (per call) | Cancels the request, including a body still streaming                                        | none           |

Error `kind` values: `invalid_input` (rejected before any request), `http` (carries `status`), `malformed_response`, `response_too_large`, `timeout`, `aborted`, `network`, `transport` (realtime), `job_failed` (video). Error messages never contain the API key or `Bearer`/`sk-` style tokens; HTTP error bodies are truncated to 500 characters. Timers and abort listeners are released on every exit path. Response bodies are read incrementally and cancelled once they exceed the cap (a larger `content-length` is refused up front).

Large downloads (video, files, speech) are held in memory: raise `maxResponseBytes` deliberately.

## Realtime transport

Global `WebSocket` implementations cannot set the `Authorization` header that OpenAI-style realtime servers require, so the package does not bundle a socket. Supply a `RealtimeTransport` whose `connect({ url, headers, signal, handlers })` opens the socket, forwards text frames to `handlers.onMessage`, close to `handlers.onClose`, errors to `handlers.onError`, and rejects if `signal` aborts first.

Session behavior: events must be JSON objects with a string `type` (otherwise the session fails and closes); at most `maxQueuedEvents` (1000) unread events, and the queue is discarded on overflow; each event ≤ `maxEventBytes` (16 MiB); `next({ timeoutMs, signal })` reads one event and returns `undefined` after a clean close (code 1000/1005); other close codes throw `transport`. `collectResponse` reads until `response.done` and throws on an `error` event. Aborting the open `signal` fails the session and closes the socket; `close()` is idempotent.
